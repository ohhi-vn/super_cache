# Design

## Context

See `proposal.md` for motivation. The baseline is the `cover/` HTML report
generated by `mix test --cover` (the `mix coveralls` alias runs
`test --cover` + `coveralls.html`), which excludes the `:cluster`-tagged peer
suite. That matters twice:

- The eight modules' remaining misses concentrate in branches that need a
  connected peer or an `:erpc` transport fault, which the default suite cannot
  produce.
- Some misses are compiler-generated default-arity wrappers (for example
  `Cluster.Rpc.call/4` and `WAL.Store.start_link/0`) or `defexception`'s
  generated `exception/1`, not missing behavior tests.

Existing assets to build on:

- `test/cluster_local_test.exs` already simulates cluster failures by planting
  `:persistent_term` partition maps and using non-connectable fake node names.
- `test/health_monitor_deep_test.exs` already covers status derivation and
  periodic cycles on a single node.
- `test/coverage_round_five_test.exs` attempts buffer restart-budget
  exhaustion, but waits only 400 ms per generation, while the backoff reaches
  seconds, so it never reaches the give-up clause.
- `tools/coverage/uncovered.exs` reads `cover/*.html` and prints miss lines for
  a hard-coded target map that omits four of the eight modules.

The suite convention is: `async: true` for pure/isolated tests, `async: false`
plus `@tag timeout: 120_000` for tests that mutate global `:persistent_term`,
GenServer state, application env, or supervision children. ExUnit runs async
modules before sync modules, so a sync test can safely perturb globals.

## Goals / Non-Goals

**Goals:**

- Reach every uncovered line that is reachable from a single, non-distributed
  VM through public functions, GenServer callbacks, injected state, or a
  documented process fault.
- Make each test's trigger explicit and deterministic; no "sleep and hope".
- Produce a reviewed residual allowlist so remaining misses are intentional.
- Keep `mix test` and `mix test.cluster` green and order-independent.

**Non-Goals:**

- Raising coverage of the `:cluster`-tagged peer suite or aggregating coverage
  across `:peer` nodes.
- Adding `meck`, `Mimic`, or any mocking dependency.
- Refactoring production modules to create test seams.
- Reaching 100% on every module where that would require a real peer or an
  unreachable defensive clause.
- A CI coverage gate (deferred; the thresholds live in the spec and are
  checked manually with the reporting tool).

## Decisions

### D1 — Tests only: no mocks, no production changes

Every reachable line is reached through real code paths. Alternatives
considered:

- **`meck` to force `SuperCache.put/1` failures or `:erpc` faults.** Rejected:
  it would add a dependency and force global module replacement for a handful
  of defensive clauses, and would make the suite fragile with any concurrent
  async test.
- **Inject seams into `Buffer`, `Stream`, and `HealthMonitor`.** Rejected: it
  changes production design for a coverage-only goal; the defensive clauses are
  cheap to keep and are documented instead.

Consequence: a small allowlist of defensive clauses stays uncovered (see
Residual Allowlist).

### D2 — Use documented seams, not private-function access

| Seam | Use |
| --- | --- |
| `:sys.replace_state/2` on `Cluster.Manager` | Add a fake remote member so `cluster_health/0` takes the remote branch |
| `:sys.replace_state/2` on `Cluster.HealthMonitor` | Set `cycle_deadline_ms: 0` to force the deadline-timeout branch; restore opts in `after` |
| `Supervisor.terminate_child/2` + `restart_child/2` on `SuperCache.Supervisor` | Stop the replicator pool and substitute a `max_children: 0` pool to make `Task.Supervisor.start_child/2` return `{:error, :max_children}` |
| Direct GenServer callback calls (`WAL.Store.init/1`) | Exercise the "table already exists" branch without a restart |
| A plain registered process under a buffer name | Make a queue ignore `:stop` so `Buffer.stop/0` hits its 1 s graceful-shutdown timeout |
| Killing buffer queue PIDs and waiting for re-registration | Drive restart backoff and the restart-budget give-up |
| Planted partition maps (`:persistent_term`) | Non-primary health checks, reachable self replicas, malformed replica lists |

Calling an `init/1` callback directly is safe for `WAL.Store`: it only ensures
tables and inserts a bookkeeping row with `insert_new/2`, so it is idempotent
against the running instance.

### D3 — File layout

Extend the focused per-module files for straightforward additions; add one new
`test/coverage_round_six_test.exs` (`async: false`) for the cross-cutting
fault-injection tests that touch supervision or restart budgets:

| Target | File |
| --- | --- |
| WAL store accessors + re-init | `test/wal_test.exs` |
| Error formatting | `test/cluster_error_test.exs` |
| RPC wrappers, exit/throw, context fallback | `test/cluster_rpc_test.exs` |
| MatchSpec list/invalid captures | `test/match_spec_test.exs` |
| Stream non-list items; poisoned batch | `test/coverage_round_six_test.exs` (batch) and `test/buffer_test.exs` |
| Buffer shutdown timeout, restart budget | `test/coverage_round_six_test.exs` |
| Replicator bulk + async retry + pool-full | `test/coverage_round_six_test.exs` |
| HealthMonitor remote/degraded/non-primary/deadline | `test/health_monitor_deep_test.exs` |

The buffer restart-budget test replaces the ineffective loop in
`coverage_round_five_test.exs` (that test is deleted or rewritten in place; it
asserts nothing today because it guards on buffer names being registered).

| --- | --- | --- | --- |

| `Cluster.Error` | 23/29 (79.3%) | 29/29 (100%) | Exercise `Error.exception/1` (covers `defexception`), non-integer partition, non-atom operation, exception struct/binary/generic reasons |
| `Cluster.Rpc` | 30/35 (85.7%) | 35/35 (100%) | 4-arity `call`/`call!`; remote function that exits and one that throws (covers the `:exit`/`:throw` catches); `normalize/2` with a non-list/non-map context |
| `Storage.MatchSpec` | 20/24 (83.3%) | 22/24 (91.7%) | `extract_bindings/1` with a list element and an invalid `:"$x"` capture; two `capture_index/1` fallbacks stay uncovered |
| `Internal.Stream` | 21/25 (84.0%) | 22/25 (88.0%) | `make_stream_pipe/1` over a non-list item (tuple) so `flush_batch/1`'s single-item clause runs; push rescue/catch stay uncovered |
| `Buffer` | 69/82 (84.1%) | 72/82 (87.8%) | Dummy queue ignoring `:stop` for the 1 s timeout; 11 kill/wait cycles for restart-budget exhaustion; birth/stop rescues and queue-race paths stay uncovered |
| `Cluster.Replicator` | 116/147 (78.9%) | 131/147 (89.1%) | 501 records to force the 500-record flush; replica = `node()` for successful `multicall`; malformed replica list for the batch/async rescue; an unreachable replica for the exhausted-retry drop branch; `max_children: 0` pool substitute for the pool-full branch. **Threshold adjustment.** The initial spec target for `Cluster.Replicator` was
90%. On OTP 29 the reachable maximum is 89.1% because lines 226 and 337 are the
classic `{replies, bad_nodes}` `:erpc.multicall/5` return shape, which this
runtime never produces. The user chose to lower the target to 89% rather than
delete the compatibility branches, so production code and OTP < 28 behavior stay
intact and the two lines are documented as residuals.

### D5 — Residual allowlist

| Module | Lines | Why unreachable in the default suite |
| --- | --- | --- |
| `Storage.MatchSpec` | 139, 142 | `capture_index/1` is only applied to atoms already accepted by `capture_atom?/1`, so its non-parsing and non-`$` fallbacks cannot run |
| `Internal.Stream` | 107–108 | `push/1` calls `SuperCache.put/1`, which is total via `safe/2`; no error can escape to the rescue |
| `Internal.Stream` | 139 | `safe_push/1`'s catch needs a throw/exit from the same total call; `safe/2` catches both |
| `Buffer` | 97–98, 136–137 | `start/1`/`stop/0` rescue clauses guard against `:persistent_term`/`spawn` BIF failures that cannot be injected from a test |
| `Buffer` | 218, 220, 230, 278 | Requires `ensure_queue/1` to fail: only reachable through a genuine `Process.register` race over 20 attempts, or a caller-level throw |
| `Buffer` | 288–289 | The `ArgumentError` retry only fires when a concurrent process takes the queue name between `Process.whereis/1` and registration |
| `Cluster.Replicator` | 170 | `flush_batch/5` already returns early on `[]`, so `send_batch/4`'s empty clause never runs |
| `Cluster.Replicator` | 226, 337 | The classic `{replies, bad_nodes}` `:erpc.multicall/5` return shape; OTP 29 returns a flat per-node result list, so these clauses cannot run on this runtime |
| `Cluster.Replicator` | 188, 190, 193–194; 390–391, 395, 397–398, 400 | Need `apply_op/3` (the only remote function) to throw or exit; it can only return or raise, and `:erpc` converts remote raises to the rescue path |
| `Cluster.Replicator` | 415–416 | Need a remote reply shaped `{:error, _, _}` or `:caught`; no public path produces those from `apply_op_batch/3` |
| `Cluster.Replicator` | 469 | Quorum `:timeout` needs a replica that accepts the connection but misses the 5.5 s deadline — requires a peer |
| `Cluster.HealthMonitor` | 198–199, 614–615, 620, 787 | Remote health success and measured replication lag need a connected peer |
| `Cluster.HealthMonitor` | 305–306 | `:synced`/`:lagging` require a non-self replica with a real lag sample |
| `Cluster.HealthMonitor` | 203 | The timeout counter needs an `:erpc` timeout, which a local/uncached call cannot produce |
| `Cluster.HealthMonitor` | 235, 279–280, 295–296, 373, 380–381, 391, 400, 693–694, 705 | Defensive `catch` clauses around `GenServer.call`/metric access; injecting them needs global mocking |
| `Cluster.HealthMonitor` | 542–543, 546, 550, 561 | Connectivity failure on `node()` itself; the local `:erpc` call cannot fail without transport mocking |
| `Cluster.HealthMonitor` | 802–804 | Timeout classifier clauses need an error whose reason is `:timeout`/`{:erpc, :timeout}`/`{:timeout, _}` from a call that cannot time out locally |

If a later change makes any of these reachable, the residual table in this
design is updated and a test is added; the spec forbids excusing reachable
lines.

### D6 — Determinism and cleanup rules

- Every global mutation (`Manager` state, `HealthMonitor` opts, partition map,
  application env, supervision child) is restored in `on_exit`/`after` even when
  an assertion fails.
- Buffer tests always end with `SuperCache.Buffer.start(...)` so subsequent
  tests see live queues; tests that register a dummy queue kill it before
  restarting.
- Replicator async tests poll `Cluster.Metrics` or storage state instead of
  sleeping for a fixed duration.
- The restart-budget test uses `wait_until/2` with a timeout derived from the
  next backoff (`min(250 * restarts, 5000) + 1_000`) rather than a constant.
- Tests that touch supervision or restart budgets are `async: false` with
  `@tag timeout: 120_000`.

### D7 — Extend the reporting tool

Add the four missing entries to the `targets` map in
`tools/coverage/uncovered.exs`:

```elixir
"SuperCache.Cluster.WAL.Store" => "lib/cluster/wal/store.ex",
"SuperCache.Cluster.Error" => "lib/cluster/error.ex",
"SuperCache.Storage.MatchSpec" => "lib/storage/match_spec.ex",
"SuperCache.Cluster.Rpc" => "lib/cluster/rpc.ex"
```

This file is developer tooling, not library code, and is explicitly allowed by
the spec.

## Risks / Trade-offs

- **Restart-budget test runtime (~14 s)** → one sequential test; keep the
  module timeout at 120 s and assert the give-up log instead of polling for a
  dead queue. The rest of the new tests are sub-second.
- **Coverage numbers are a moving target while two other changes touch the
  same modules** (`improve-performance-stability-consistency`,
  `harden-distributed-reliability`) → the spec sets thresholds, not exact
  files; if those changes land first, re-measure and only add tests for newly
  uncovered lines.
- **Planted GenServer state can mask real behavior** → only mutate the minimum
  (`Manager.nodes`, `HealthMonitor.opts`) and always restore; prefer public
  APIs for the assertion.
- **`cycle_deadline_ms: 0` could theoretically let the task finish before
  `Task.yield/2` returns** → the assertion accepts either a `:fail`/`:unknown`
  timeout record or a normal pass, but the test also asserts the timeout metric
  only when the deadline branch was observed; if it proves flaky in practice,
  call the `handle_call(:force_check, ...)` callback directly with the zero
  deadline.
- **Buffer dummy-queue test leaves a runner blocked on the dummy** → kill the
  dummy, restart buffers, and wait for both real queue PIDs before completing
  the test.

## Migration Plan

None. Tests and a developer script only; roll back by reverting the test files
and the `tools/coverage/uncovered.exs` entry list. No configuration, data, or
deployment changes.

## Open Questions

- Whether to add an automated coverage gate (for example a `mix coverage.check`
  task or CI step) is deferred; the spec's thresholds are checked manually for
  now.
